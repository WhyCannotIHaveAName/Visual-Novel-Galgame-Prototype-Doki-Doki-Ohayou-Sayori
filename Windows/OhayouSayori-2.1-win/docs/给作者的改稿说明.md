# 以后写故事，只需要先看这几行

你不需要先把 Python 学完。Ren’Py 的对白部分可以直接当成「带舞台指令的剧本」来写。

## 最常改的文件

| 文件 | 负责什么 |
| --- | --- |
| `game/story.rpy` | 正篇和五篇小剧场；台词、出场、选择、跳转 |
| `game/characters.rpy` | 谁在说话、名字显示成什么颜色 |
| `game/assets.rpy` | 图片名字与实际文件的对应关系 |
| `game/bookmarks.json` | 手册里的 17 个章节入口 |
| `game/systems.rpy` | 成就、章节记录、配乐切换；普通改稿不用动 |
| `game/presentation.rpy` | 标题页、手册、结局明信片的样子 |
| `game/screens.rpy` | Ren’Py 的存档、读档、设置、历史等界面 |

## 一个可以读懂的小场景

```renpy
label new_morning:
    scene bg campus with dissolve
    show sayori happy at solo
    sayori "早上好！"
    mind "她今天似乎很开心。"

    menu:
        "一起去吃早饭":
            jump breakfast
        "先去上课":
            jump classroom_morning
```

`label` 是这一段的地址。`scene` 换背景，并清掉上一场的人物；`show` 让人物登场；`jump` 去另一个地址。缩进请用四个空格，同一层对齐。双引号内才是玩家看到的文字。

上面的两个目标只是示例；真正放进游戏时，要同时写好对应的 `label breakfast:` 和 `label classroom_morning:`。不要重用已经存在的地址。

## 表情和站位

`show sayori happy at solo`：Sayori 高兴，站在中间。

`show obedience normal at duo_left` 与 `show leo normal at duo_right`：两人左右站立。三人可用 `trio_left`、`solo`、`trio_right`，四人用 `quartet_1` 到 `quartet_4`。

同一人物换表情，直接再写一行 `show` 即可。离场用 `hide sayori with dissolve`。同一场景里换背景会清掉人物，想让她继续站着就再 `show` 一次。

图片到底有哪些名字，以 `assets.rpy` 为准。更换素材时，先放进 `game/images`，再改那里的文件名；不必把整篇剧情中的 `show` 重写一遍。

## 成就和结局

已有成就沿用原来的名字，例如 `$ grant_achievement("拥抱1")`。重复得到不会重复计数。新增成就需要同时加入 `systems.rpy` 对应分组，不能只在剧情里随便发一个新名字。

结局的顺序很重要：

```renpy
    $ grant_achievement("结局1")
    call ending_card(1)
    return
```

先登记，再展示，再结束。`return` 后面的代码不会继续执行，这正是旧版结局无法解锁的主要原因。`call` 会记住回来的位置；`jump` 只管前往下一段，不会回来。

## 验证一小段修改

1. 在 Ren’Py 启动器中选本项目，点「检查脚本」。它能发现拼写、缺图、跳转等静态问题。
2. 从主菜单「调试室」搜索章节，直接测试修改的地方，看看文字有没有遮挡、人物是否站对位置、选择能否到达预期后果。
3. 只改对白通常不用碰其他系统。若修改结局跳转，则还应验证成就、回看和存读档。

开发用的 `qa_checks.rpy`、`qa_routes.rpy` 提供自动运行测试，玩家包不会包含它们。`tools/verify.ps1` 可以在指定 SDK 下依次运行检查与测试。它会复制临时项目，排除你已有的存档，再在副本中测试；不会替你把正式游戏全部解锁。不要直接在自己正在玩的工程里调用 `qa_suite`。

旧存档可能保存了旧版脚本的位置。大量移动、删除剧情段落后，最可靠的核对方式是新开一局；请保留修改前的项目副本。

## 调试室与新立绘

主菜单「调试室」随时可进。选择角色分类或搜索 `chapter1007` 等地址；点击一行即开始独立测试。先设置计数和 Sayori 判定，再进入章节。F6 开关开启后，在剧情里可直接呼出调试室。测试不会增加成就或已读章；结束测试返回原先位置。

「立绘与同屏比例」可切换人物、表情、1/2/4 人同屏和底色。四人布局固定为四位女主；检查 Leo 或 Shane 请选单人或双人。不要对单张表情图随意增加 zoom，否则换表情时会跳动。新的图都以 `v21_` 开头，旧 `happypink/hugpink/surprisepink` 名字仍能用，已映射到统一服装。

调试入口目录在 `game/debug_scenes.json`；添加章节后，追加 `["新label", "章节说明", "分类"]` 即可。演出代码集中在 `game/horror.rpy`，可用 `call horror_signal(1)` 或 `call horror_cut("portrait", 2.0)` 插入，关闭效果时会自动略过。
